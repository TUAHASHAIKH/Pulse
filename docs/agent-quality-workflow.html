Pulse agent quality workflow

End-to-end review pipeline from the agent quality overhaul: richer context, evidence checks, confidence gates, patch validation, and optional auto-delivery of fixes.

Problem this workflow solves Agents were producing duplicate findings, hallucinated issues, broken patches, and false positives because they saw only a raw diff. The pipeline now builds file context first, then filters, then repairs only high-confidence issues.

Quality gates in order

Finding quality

Each finding must include an evidence snippet that actually appears in the diff. Strict validation also checks file membership, line mapping, and domain category slugs.

Post-parse filters drop low-confidence items and cap each agent at 5 findings.

Evidence required Confidence floor Max 5 / agent

Repair quality

The repair agent receives the authoritative file, not just the hunk. Suggested reviewer fixes are labeled as unverified hints.

Patches are checked with git apply before Docker tests. If Docker is unavailable the status is UNVERIFIED, not succeeded.

Full-file patch git apply --check UNVERIFIED without Docker

Implemented in four phases

Phase 1 — Signal quality Done

Evidence field, UNVERIFIED repair status, quality settings, stricter prompts, confidence gate, same-category dedup, repair only for critical/warning ≥ 0.7.

Phase 2 — Context Done

Structured diff parser, context builder, finding validator, shared base reviewer, architect skip for docs, graph state with project_root / file_context / parsed_hunks.

Phase 3 — Patches Done

Patch validator, repair against full file, hunk-only original diff, repair_max_attempts from settings, Docker-unavailable marked UNVERIFIED.

Phase 4 — Feedback loop Done

Unit tests, false-positive button, evidence in Findings panel, quality thresholds in Settings, CLI sends project_root, auto-deliver via fix_delivery, real GitHub branch commits.

Repair and delivery path

After a patch is produced, delivery is separate from generation. Default is still Ask so the dashboard buttons apply the fix.

Before vs after

Before

Agents reviewed a raw diff with no file context.

Duplicates merged across unrelated categories.

First finding could force a repair attempt.

Missing Docker was reported as a successful repair.

Branch “commit” stored the patch in the message only.

After

Hunks plus full file, imports, siblings, and tests.

Dedup only when category matches; evidence required.

Repair only for high-confidence critical/warning.

UNVERIFIED until Docker tests pass.

Git Data API writes real file blobs on the fix branch.

Known gap outside this workflow Local GitHub automation (hooks install, one-shot run-review, optional daemon) was planned separately and is not part of this quality pipeline.
